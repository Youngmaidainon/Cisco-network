# Cisco Packet Tracer Multi-Level Network Architecture Portfolio

คลังรวมโปรเจกต์การออกแบบและจัดคอนฟิกระบบเครือข่ายคอมพิวเตอร์ (Network Architecture) บนโปรแกรม Cisco Packet Tracer โดยเรียงลำดับจากระดับพื้นฐานระดับใช้งานจริงในธุรกิจขนาดเล็ก ไปจนถึงระดับสถาปัตยกรรมเครือข่ายองค์กรขนาดใหญ่ที่มีความปลอดภัยและเสถียรภาพสูง (Enterprise & High Availability)

---

## 📂 โครงสร้างพอร์ตโฟลิโอ (Portfolio Structure)

* **Level 1: SOHO Network** - ระบบเครือข่ายสำนักงานขนาดเล็ก/โฮมออฟฟิศ
* **Level 2: Campus LAN with VLANs** - ระบบเครือข่ายภายในอาคารแยกแผนกเพื่อความปลอดภัย
* **Level 3: Enterprise Network with Redundancy** - ระบบเครือข่ายหลักองค์กรใหญ่ที่เน้นความเสถียร (ห้ามล่ม)
* **Level 4: Multi-Site WAN & Security** - ระบบเชื่อมต่อเครือข่ายข้ามจังหวัดและความปลอดภัยขั้นสูง

---

## 🟢 Level 1: SOHO Network (Small Office / Home Office)

### 🎯 จุดประสงค์ของโปรเจกต์
* เพื่อจำลองสถาปัตยกรรมระบบเครือข่ายระดับเริ่มต้นสำหรับธุรกิจขนาดเล็ก Startup หรือ Co-working Space ที่มีพนักงานจำนวนไม่เกิน 20 คน
* มุ่งเน้นการจัดการระบบเครือข่ายให้พนักงานสามารถเข้าใช้งานอินเทอร์เน็ตได้อย่างปลอดภัยทั้งรูปแบบสาย LAN และคลื่นสัญญาณไร้สาย (Wi-Fi)
* ฝึกฝนการเปิดใช้งานบริการแจกจ่ายไอพีอัตโนมัติ (DHCP Server) เพื่อลดความซ้ำซ้อนและภาระงานของผู้ดูแลระบบในการตามแก้ไขไอพีทีละอุปกรณ์
* ประยุกต์ใช้งานเทคโนโลยี NAT (Network Address Translation) รูปแบบ Overload (PAT) เพื่อแปลง Private IP ภายในองค์กรให้ใช้งาน Public IP เดียวกันออกสู่อินเทอร์เน็ตได้อย่างคุ้มค่า

### 🔬 เกณฑ์และวิธีการทดสอบระบบ (Verification Checklist)
* **การทดสอบระบบ DHCP:** * เปิดพอร์ตคอมพิวเตอร์ `PC-Admin` เปลี่ยนโหมดเป็น DHCP อุปกรณ์ต้องได้รับ IP Address ในวง `192.168.1.0/24` พร้อม Gateway (`192.168.1.1`) และ DNS Server (`8.8.8.8`) ครบถ้วนโดยไม่มีค่าว่าง
* **การทดสอบระบบเชื่อมต่อ Wi-Fi:** * อุปกรณ์ `Laptop-Wireless` ต้องสามารถเชื่อมต่อสัญญาณ (Link Link) กับ `Wi-Fi-Router` และได้รับ IP Address วงภายในอย่างถูกต้อง
* **การทดสอบการเชื่อมต่อปลายทาง (End-to-End Connectivity):** * เปิดหน้าต่าง Command Prompt บน `PC-Admin` พิมพ์คำสั่ง `ping 8.8.8.8` (เซิร์ฟเวอร์อินเทอร์เน็ตจำลอง) ระบบต้องตอบกลับเป็น *Reply from 8.8.8.8* ทั้งหมด 4 บรรทัด
* **การตรวจสอบตาราง NAT บนเราเตอร์:** * เข้าหน้าจอ CLI ของ `R1-SOHO` พิมพ์คำสั่ง `show ip nat translations` ระบบต้องแสดงตารางการจับคู่ระหว่าง Inside Global (Public IP) และ Inside Local (Private IP) ในขณะที่คอมพิวเตอร์กำลังรับส่งข้อมูลออกสู่ภายนอก

## 🟡 Level 2: Campus LAN with VLANs

### 🎯 จุดประสงค์ของโปรเจกต์
* เพื่อออกแบบโครงสร้างเครือข่ายสำหรับอาคารสำนักงานขนาดกลางที่มีการแบ่งสัดส่วนพนักงานออกเป็นแผนกต่างๆ (เช่น IT, HR, Finance)
* มุ่งเน้นการบริหารจัดการทราฟฟิกข้อมูลด้วยเทคโนโลยี VLAN (Virtual LAN) เพื่อตัดขาดการมองเห็นและจำกัดสิทธิ์การเข้าถึงข้อมูลลับข้ามแผนก
* ฝึกฝนการทำ Inter-VLAN Routing ด้วยเทคนิค Router-on-a-Stick โดยใช้สายสัญญาณหลัก (Trunk Link) เพียงเส้นเดียวในการนำส่งข้อมูลของทุกกลุ่มระบบ
* ประยุกต์ใช้งานเทคโนโลยี EtherChannel (Link Aggregation) เพื่อรวมพอร์ตเชื่อมต่อระหว่างสวิตช์เพิ่มขนาดท่อส่งข้อมูล (Bandwidth) และทำเป็นลิงก์สำรองกันระบบขาด
* เสริมสร้างความปลอดภัยระดับฮาร์ดแวร์ด้วย Port Security เพื่อป้องกันบุคคลภายนอกลักลอบนำอุปกรณ์แปลกปลอมมาเชื่อมต่อสาย LAN ของบริษัท

### 🔬 เกณฑ์และวิธีการทดสอบระบบ (Verification Checklist)
* **การตรวจสอบฐานข้อมูล VLAN:** * พิมพ์คำสั่ง `show vlan brief` บนสวิตช์ `SW-Floor1` และ `SW-Floor2` พอร์ตใช้งานต้องถูกย้ายเข้าไปอยู่ในวง VLAN 10, 20, 30 ตามแผนกที่กำหนดไว้อย่างสมบูรณ์
* **การทดสอบสถานะสายเชื่อมต่อสวิตช์ (EtherChannel):** * พิมพ์คำสั่ง `show etherchannel summary` บนสวิตช์ ต้องแสดงสถานะเป็นพอร์ตกลุ่มคู่ (เช่น Po1) และระบุตัวอักษรสถานะเป็น `(SU)` ซึ่งหมายถึง Layer 2 และ Up ในการใช้งาน
* **การทดสอบสิทธิ์การติดต่อสื่อสารระหว่างแผนก (Inter-VLAN):** * ทดสอบสั่ง `ping` ข้ามวงจากแผนก IT ไปแผนก HR ระบบต้องสามารถติดต่อได้สำเร็จเนื่องจากผ่านการเราติ้งบน Sub-Interface ของเราเตอร์หลัก
* **การทดสอบระบบความปลอดภัยพอร์ต (Port Security):** * ทำการจำลองสถานการณ์โดยลากคอมพิวเตอร์เครื่องใหม่ (Attacker) มาเสียบสาย LAN แทนที่พอร์ตของ `PC-IT-1` สวิตช์ต้องทำการปิดพอร์ตนั้นทันที สัญญาณไฟจะเปลี่ยนจากสีเขียวเป็นสีแดง และพอร์ตจะระบุสถานะเป็น `err-disable` (Shutdown)

## 🟠 Level 3: Enterprise Network with Redundancy (High Availability)

### 🎯 จุดประสงค์ของโปรเจกต์
* เพื่อจำลองสถาปัตยกรรมระบบเครือข่ายสำหรับแกนหลัก (Core Network) ขององค์กรขนาดใหญ่หรือโรงงานอุตสาหกรรมที่ระบบโครงสร้างพื้นฐาน "ห้ามล่มเด็ดขาด"
* มุ่งเน้นการออกแบบสถาปัตยกรรมแบบทนทานต่อความเสียหาย (Fault Tolerance) โดยใช้อุปกรณ์คอร์สวิตช์และเราเตอร์ขนานคู่กันแบบ Active-Standby
* ศึกษาและคอนฟิกโปรโตคอลระบบเกตเวย์สำรอง HSRP (Hot Standby Router Protocol) เพื่อให้ผู้ใช้งานภายในสามารถเข้าถึงอินเทอร์เน็ตได้ต่อเนื่องแม้มีอุปกรณ์หลักพังเสียหาย
* ฝึกฝนการเปิดใช้งานโปรโตคอลการหาเส้นทางแบบไดนามิก OSPF (Open Shortest Path First) เพื่อให้อุปกรณ์เน็ตเวิร์กเรียนรู้แผนผังระบบและปรับเปลี่ยนทิศทางข้อมูลเองอัตโนมัติ
* ปรับแต่งค่า Spanning Tree Protocol (STP/RSTP) เพื่อป้องกันปัญหาการเกิดสัญญาณวนลูป (Network Loop) จากการต่อสายสำรองแบบใยแมงมุม

### 🔬 เกณฑ์และวิธีการทดสอบระบบ (Verification Checklist)
* **การตรวจสอบสถานะเกตเวย์สำรอง (HSRP Status):** * พิมพ์คำสั่ง `show standby brief` บน `Core-SW1` ต้องระบุสถานะตนเองว่าเป็น `Active` และชี้เป้าตัวสำรองไปที่ไอพีของ `Core-SW2` ในขณะที่เมื่อพิมพ์คำสั่งเดียวกันบน `Core-SW2` จะต้องแสดงสถานะตนเองเป็น `Standby`
* **การตรวจสอบตารางเส้นทางไดนามิก OSPF:** * พิมพ์คำสั่ง `show ip route` บนคอร์สวิตช์และเราเตอร์หลัก ในตารางการเราติ้งต้องปรากฏเส้นทางของเน็ตเวิร์กวงต่างๆ โดยมีตัวอักษรนำหน้าเป็นตัว **`O`** ยืนยันว่า OSPF แลกเปลี่ยนข้อมูลสำเร็จ
* **การทดสอบการสลับสายอัตโนมัติเมื่อเกิดเหตุขัดข้อง (Failover Test):** * เปิดหน้าต่างคอมพิวเตอร์ผู้ใช้งานแล้วใช้เครื่องมือจำลองการส่งข้อมูลแบบต่อเนื่อง หรือตรวจเช็คสถานะการเชื่อมต่อ 
    * ทำการกดลบสายแลนหลักระหว่าง `Core-SW1` และ `Access-SW1` ออกจากระบบ 
    * เครือข่ายต้องทำงานต่อได้ทันที ทราฟฟิกข้อมูลจะสลับไปวิ่งผ่าน `Core-SW2` โดยอัตโนมัติในเศษเสี้ยววินาที (อาจมี Packet Drop เกิดขึ้นเพียง 1-2 แพ็กเก็ตเท่านั้น)

## 🔴 Level 4: Multi-Site WAN & Security

### 🎯 จุดประสงค์ของโปรเจกต์
* เพื่อจำลองการเชื่อมต่อระบบเครือข่ายระดับแอดวานซ์ระหว่างสำนักงานใหญ่ (HQ) และโรงงานสาขาย่อย (Branch) ที่ตั้งอยู่ต่างพื้นที่ผ่านโครงข่ายอินเทอร์เน็ตสาธารณะ
* มุ่งเน้นการสร้างอุโมงค์ส่งข้อมูลปลอดภัยสูงด้วยเทคโนโลยี Site-to-Site VPN (GRE over IPsec) เพื่อเข้ารหัสลับข้อมูลทุกชนิด ป้องกันการดักฟังและการโจรกรรมข้อมูล
* ฝึกฝนการใช้สถาปัตยกรรมเครือข่ายไร้สายยุคใหม่แบบควบคุมจากส่วนกลาง (Centralized Wireless Architecture) ผ่านอุปกรณ์ Wireless LAN Controller (WLC)
* พัฒนาระบบรักษาความปลอดภัยเครือข่ายด้วยการยืนยันตัวตนผ่านเซิร์ฟเวอร์กลาง AAA (Authentication, Authorization, and Accounting) ด้วยโปรโตคอล RADIUS
* ออกแบบและเขียนกฎควบคุมการเข้าถึงกลุ่มข้อมูล (Extended Access Control Lists - ACLs) ทำหน้าที่เป็นไฟร์วอลล์สกรีนทราฟฟิกและสิทธิ์การเข้าใช้งานเซิร์ฟเวอร์การเงิน

### 🔬 เกณฑ์และวิธีการทดสอบระบบ (Verification Checklist)
* **การตรวจสอบสถานะการเชื่อมต่ออุโมงค์ VPN:** * พิมพ์คำสั่ง `show crypto isakmp sa` บนเราเตอร์ฝั่งสำนักงานใหญ่และสาขาย่อย สถานะในตารางผลลัพธ์จะต้องขึ้นคำว่า **`QM_IDLE`** ซึ่งเป็นเครื่องหมายยืนยันว่ากระบวนการตกลงแลกเปลี่ยนคีย์และเข้ารหัส IPsec เฟส 1 สำเร็จเสร็จสิ้นอย่างปลอดภัย
* **การตรวจสอบการควบคุมเสาไร้สายผ่านส่วนกลาง:** * เข้าใช้งาน Web Browser จากคอมพิวเตอร์ `HQ-Admin` พิมพ์ไอพีรีโมทเข้าหน้าจอ GUI ของ `HQ-WLC` (`172.16.10.5`) ในหน้าจอ Dashboard หลักต้องตรวจพบเสาอากาศ `HQ-AP` และ `BR-AP` วิ่งเข้ามาลงทะเบียน (Registered) เกาะระบบควบคุมเรียบร้อย
* **การทดสอบการคัดกรองข้อมูลของไฟร์วอลล์ (ACL Enforcement):** * ใช้คอมพิวเตอร์ผู้ดูแลระบบ `HQ-Admin` ทดสอบเปิดเว็บบราวเซอร์ระบุไอพีของ `Finance-Server` (`172.16.10.200`) ระบบต้องยอมให้เปิดเข้าหน้าเว็บได้สำเร็จ 
    * ในทางกลับกัน เมื่อใช้คอมพิวเตอร์ของพนักงานทั่วไปทดสอบเปิดใช้งานไปที่ไอพีเดียวกัน ระบบต้องขึ้นข้อความปฏิเสธการเชื่อมต่อ (*Connection Timeout*) เพื่อพิสูจน์ว่ากฎ ACL บล็อกทราฟฟิกที่ไม่ได้รับสิทธิ์ได้จริง
* **การทดสอบการล็อกอินผ่านระบบ AAA RADIUS:** * เมื่ออุปกรณ์พยายามล็อกอินเข้าระบบเครือข่ายไร้สายหรือเข้าโหมดบริหารจัดการ จะต้องมีการเด้งถาม Username/Password โดยเราเตอร์จะวิ่งไปตรวจสอบข้อมูลความถูกต้องจากตารางรายชื่อใน `Radius-Server` ก่อนอนุมัติสิทธิ์เสมอ

## 🛠️ วิธีการนำไฟล์ไปใช้งาน (How to Use)

1.  ดาวน์โหลดและติดตั้งโปรแกรม **Cisco Packet Tracer** (แนะนำเวอร์ชัน 8.x ขึ้นไป เพื่อรองรับ Licence คำสั่งและรุ่นอุปกรณ์ทั้งหมด)
2.  ทำการ `Clone` หรือดาวน์โหลดไฟล์ Repository นี้ลงบนเครื่องคอมพิวเตอร์ของคุณ
3.  เลือกเปิดไฟล์สถาปัตยกรรมที่ต้องการทดสอบ เช่น `Level-4-MultiSite-WAN-Security/MultiSite_Secure_WAN.pkt`
4.  ตรวจสอบสัญญาณไฟบนพอร์ตเชื่อมต่อ (ต้องเป็นสีเขียวทุกจุด) หากพบไฟสีส้ม ให้กดปุ่ม **`Fast Forward Time`** ด้านล่างซ้ายเพื่อเร่งเวลาของโปรโตคอล STP
5.  สามารถศึกษาโค้ดคำสั่งจัดคอนฟิกแบบเต็มรูปแบบได้จากไดเรกทอรีของแต่ละเลเวล หรือกดเข้าโหมด CLI บนตัวอุปกรณ์เพื่อพิมพ์คำสั่งตรวจสอบสถานะตามแนวทางใน Verification Checklist
